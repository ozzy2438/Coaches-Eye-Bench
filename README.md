# Coaches' Eye Bench

An open, reproducible benchmark that asks one question an AFL club actually cares about:

> **When AFL coaches judge who mattered most in a match, how much of that judgement can a transparent model built from public match statistics reproduce — where does it agree, and where do the stats systematically miss what coaches see?**

Ground truth: the **AFL Coaches Association (AFLCA) votes** — after every home-and-away match both senior coaches give 5-4-3-2-1 votes (max 10 per player, 30 per match). Independent project; **not affiliated with any club or the AFL.**

## Run the benchmark

Prerequisites: Python 3.11+ with `uv`, R >= 4.1, and HTTPS access to the sources in
`DATA.md`. R package installation may also need a C/C++ compiler and the development
headers for libcurl, OpenSSL and libxml2. Python dependencies are locked by `uv.lock`;
the fetch requires fitzRoy 1.8.0. `renv.lock` pins all 49 R packages used by the
fetch; `make setup-r` restores those exact versions into `.r-library`. The lock
records R 4.5.0; use that R version to reproduce the verified environment.

```bash
export CEB_CONTACT_EMAIL=you@example.org   # goes into the User-Agent of every scrape
make setup && make setup-r
make smoke                   # offline synthetic check
make data-pilot              # 2024–2025 fetch, join, QA and reduced real-data smoke
make data                    # complete development data, 2012–2025
```

* `make data` — R + [fitzRoy](https://github.com/jimmyday12/fitzRoy) (pinned 1.8.0) fetches only the requested seasons' AFL Tables pages and AFLCA votes, caches them, writes a SHA-256 manifest, runs the name join and the data-quality checks. The all-seasons fitzRoy statistics cache is deliberately not loaded: it could contain the locked test season.
* `make data-pilot` — uses 2024–2025 only. Raw files are reusable by `make data`; processed tables, reduced model choices and smoke outputs are isolated under `data/pilot` and `results/pilot`. These choices are never used for the final study. A failed join still writes the unmatched-row and exclusion reports.
* `make smoke` — the whole pipeline (ingest → join → QA → models → bootstrap → Holm → blind spots → trends → report) on a **synthetic fixture**, offline, ~15 s. It proves the machinery runs and recovers planted effects; its output is stamped `SYNTHETIC` and is never a result.

The full study, in order: `make train` (selection on validation only) → `make eval-val` → `make eval-test` (single guarded run on 2026) → `make report`. `make test` runs the 75 tests; `make smoke-real` is a plumbing check on two real dev seasons.

## Protocol and integrity

[`protocol.md`](protocol.md) was written, committed and tagged **`protocol-frozen`** *before any implementation existed and before any 2026 data was loaded*. Its parameters live in one machine-readable block that the code reads — there is no second copy to drift.

| Rule | Where it is enforced |
|---|---|
| Time splits: Train 2012–2023, Validation 2024–2025, **Test 2026 locked** | `splits.make_splits` refuses test rows unless called by the guarded test run |
| Test season is not even fetched before the freeze | `make data-test` and `r/fetch.R` check the tag; dev manifests never open test files |
| Selection on validation only; frozen choices written before the test | `results/val/frozen_choices.json` |
| Test evaluated **once** | `make eval-test` refuses without the tag, if `protocol.md` differs from the tag, without frozen choices, or if `results/test/test_run.json` already exists |
| No leakage | token-based guard on every feature view; Brownlow votes are a second *target* only |
| Name-join ≥ 99% per season and overall, every miss logged | `join.check_join_rate` stops the pipeline |
| Votes sum to 30 per match, no duplicates, sane ranges, no test rows in dev data | `qa.run_qa` (pandas) re-checked independently in SQL (DuckDB) |

Departures from the protocol go in [`DEVIATIONS.md`](DEVIATIONS.md); agent-chosen defaults and every judgement call are in [`DECISIONS.md`](DECISIONS.md).

## Models (Q1)

| | Model | Idea |
|---|---|---|
| B0 | Disposals | what media rank by |
| B1 | Fantasy points | AFL Fantasy weights on box-score counts, zero training |
| M1 | Interpretable | L2-penalised proportional-odds model on 21 stats + won/margin; coefficients a coach can read |
| M2 | Complex | LightGBM LambdaRank grouped by match |

Primary metric: NDCG@5 per match with votes as gains (tie-aware, match-level bootstrap CIs, Holm-corrected paired tests). The decision rule uses δ = 0.01 NDCG@5 as a pre-specified research threshold, not a measured threshold of usefulness to a coach. Meeting it warrants considering M2; adoption still requires practitioner evaluation.

The secondary **Normalized Recall@5** divides expected top-five hits by `min(5, vote receivers)`. It is not conventional recall (hits / all receivers). The historical JSON key `recall5` and frozen calculation are retained; reports use the explicit name.

**Q2** — blind spots by role proxy / match closeness / team, plus coaches vs umpires (Brownlow). **Q3** — how M1's coefficients move across season blocks (bootstrap CIs, only clearly-separated changes reported).

## How the machinery was verified (no real data needed)

* NDCG@k equals scikit-learn's tie-aware implementation and a brute-force average over all tie-breaks; Recall/Top-1/Spearman have hand-checked cases.
* The ordinal model's gradient matches finite differences and its unpenalised fit matches `statsmodels.OrderedModel`; the bootstrap CI covers the truth ~95% of the time.
* Planted-effect tests on synthetic data (3 scenarios, `tests/test_recovery.py`): when a non-linear effect is planted the decision rule says "M2 justified"; when none is planted it says "not justified"; a planted trend in tackles is found (Holm-adjusted p < 0.001) and no trend is invented when none exists.
* **A limitation this exposed:** the protocol's role-residual lens (H2a: *defenders under-rated*) has almost no power to detect unrecorded work. In three synthetic scenarios (`scripts/h2a_sensitivity.py`) the defender residual's lower 95% bound never exceeded 0 — not even with a planted premium about four times the goals weight (+0.005 [−0.025, +0.034]); at a premium equal to the goals weight it was +0.033 [0.000, +0.067]. The stat profile that defines the role proxy lets the model absorb the premium. A "not supported" verdict on real data is therefore weak evidence of absence. The analysis is reported exactly as specified; a labelled post-hoc M2-residual lens is added (it does no better); independent position labels would be the real fix.

## Limitations

* **Public box scores only** — no tracking/GPS, no Champion Data metrics, no off-ball work, no opposition context.
* **Coaches' votes are subjective** and may carry reputation bias; each match has exactly two voters, both from the clubs playing. "Agreement with coaches" is not "correctness".
* **Agreement ≠ causation.** This is a post-match evaluation lens, not a predictor, and says nothing about player value over a career.
* **The role proxy is a heuristic** from box scores (no position labels in the sources); see above for what it can and cannot show.
* Q2 role residuals describe disagreement with M1; they cannot establish that public statistics omit defensive work. Independent position labels would improve role validity, but would not by themselves establish causation or fix model misspecification. The signed mean residual by match closeness is structurally zero because predictions are rescaled to 30 per match; that lens must not be interpreted as evidence of equal accuracy across match contexts.
* **Logit-scale coefficients** in the trend analysis are relative to residual noise: when one weight rises, others can look smaller. The protocol's "clearly separated" rule is applied as written and reported next to Holm-adjusted p-values.
* **Validation figures for M1/M2 can be optimistic** because the specification was selected on those same seasons. Their conditional intervals omit selection uncertainty; the size of that optimism is unknown. The independent 2026 evaluation is reported separately; its match-bootstrap intervals condition on the refitted models and do not cover training or future-season uncertainty.
* 2020 had shortened quarters; within-match standardisation (the `match_z` view) mitigates but does not remove it.
* The vote scraper depends on fitzRoy internals (pinned) and on the AFLCA site layout.
* AFLW replication (stretch) is not done.

## How this was built

The research question, the choice of AFLCA votes as ground truth, the time-split design, the model families and the primary metric were written by the human owner (the project brief). An AI coding agent (Claude Code) implemented the code, the tests and the remaining protocol defaults, and froze the protocol in git *before* implementing anything. The agent could not reach the live data sources from its sandbox (egress policy), so **it never ran the study on real data** — it verified every component with independent checks (above), synthetic fixtures with planted truth, and an SQL re-check, and left the real run as the owner's two commands.

The subsequent development run completed `make data`, `make train`, `make eval-val`
and `make report` on real 2012–2025 data. It retains 2,752 matches (123,122
player-matches), trains on 2012–2023 and evaluates on all 414 matches in 2024–2025.
The documented source-identity corrections preserve the numerical gates and
tagged protocol; pilot choices remain isolated. Season rates and exclusions are
in [`results/DEVELOPMENT_QA.md`](results/DEVELOPMENT_QA.md), and full validation
results and limitations are in [`results/RESULTS.md`](results/RESULTS.md).
`renv.lock` fixes 49 R package versions and passed an independent empty-library
restore.

The authorized single 2026 evaluation completed on 1 October 2026 after the
pre-test commit `144f017` recorded 78 frozen file hashes in
[`results/TEST_FREEZE.json`](results/TEST_FREEZE.json). All 78 matched after the
evaluation; the protocol, dependency locks, model code and frozen choices were
unchanged. The models were refitted on 2012–2025 and evaluated on 206 of 207
home-and-away matches (9,476 player-matches). One Round 9 fixture was excluded
because a junior-name suffix prevented the frozen join from matching a vote row;
no test-based alias correction was applied. Row and vote-mass match rates were
99.926% and 99.839%; all QA gates passed.

M1 exceeded both baselines. M2 had a statistically positive primary difference,
but its lower confidence bound did not clear the frozen 0.01 research threshold.
Its Top-1 and Spearman differences were not statistically established, while
Normalized Recall@5 improved. No model, parameter or threshold was changed
after seeing these results. Q2/Q3 retain their development-data scope and
limitations: H2a is unsupported, and none of the five pre-named Q3 features
passes the first-versus-last Holm test. The test receipt
[`results/test/test_run.json`](results/test/test_run.json) blocks another test run.
Only aggregate and derived outputs are published; raw tables and player-level
votes, statistics and scores remain local and ignored by git.
